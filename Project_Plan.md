# IS355 Project Plan 
## By Colin Muller, Collin Morris, Kairi Thomas and Mohammad Abukhdeir 

## Group and GitHub Repository

Our project group has been formed, and a shared GitHub repository has been created for the IS355 Networking and Cyber Security project.

All group members will contribute regularly to the repository throughout the project. Each member will make commits when completing meaningful work, including writing report sections, researching cloud services, completing the risk assessment, or creating and updating network diagrams.

---

## Communication Plan

The group will communicate primarily through **group text messaging** for quick updates, questions, and coordination.

We will meet **twice each week**:

- **During our scheduled class/tutorial time** to discuss progress and work on project tasks.

Additional meetings may be arranged when necessary, especially before major project deadlines.

All group members are expected to communicate if they are unable to complete an assigned task so that work can be redistributed before a deadline.

---

## Project Timeline

| Week | Planned Tasks |
|------|---------------|
| **Week 4** | Form project group, create GitHub repository, establish communication plan, and create project timeline. Begin reviewing the company scenario and identifying network requirements and assumptions. |
| **Week 5** | Complete the initial list of assumptions and requirements. Begin planning the network structure, including factory, office, security camera, server, and wireless networks. |
| **Week 6** | Determine IP addressing and subnet allocation. Identify required networking equipment and begin creating the network diagram in diagrams.net. |
| **Week 7** | Complete the first draft of the network design. Write explanations and justifications for major network design decisions and recommended hardware. |
| **Week 8** | Upload the draft network design and at least one network diagram to GitHub. Review the network design as a group and make corrections where necessary. |
| **Week 9** | Research two cloud providers. Determine comparable specifications and calculate annual pricing for the web server and backup server. Save cloud pricing calculator exports to GitHub. |
| **Week 10** | Complete the cloud services comparison and recommendation. Compare local backups, encrypted cloud backups, and unencrypted cloud backups. Document group members' approaches to backing up university work. |
| **Week 11** | Conduct the cybersecurity risk assessment. Identify and classify at least six important assets and identify relevant threats and vulnerabilities. Complete the required risk assessment spreadsheet. |
| **Week 12** | Identify and justify at least six security controls based on the highest risks. Connect each control to appropriate standards or industry best practices such as the NIST Cybersecurity Framework. Update the network design where security controls affect the architecture. |
| **Week 13** | Review and improve all report sections. Complete the project reflection and contribution statement. Verify that all required diagrams, screenshots, spreadsheets, cloud pricing exports, and supporting files are properly linked in the Markdown report. |
| **Final Week** | Perform a final group review for accuracy, formatting, and completeness. Confirm that all group members have made regular GitHub commits. Download the final GitHub repository as a ZIP and submit it to Moodle. Do not make changes to the GitHub repository after Moodle submission. |

## Work Allocation

Although individual group members may take the lead on particular sections, all members will review and contribute to each major project task.

Work will be distributed as evenly as possible, and each member will maintain regular GitHub activity throughout the project.

Specific task assignments will be discussed and updated during weekly group meetings as the project progresses.

---

## GitHub Contribution Expectations

All group members will:

- Make regular commits throughout the project.
- Aim to make at least one meaningful contribution each week.
- Use clear commit messages describing the work completed.
- Review work completed by other group members.
- Ensure their individual contributions can be identified through the GitHub commit history.
- Avoid waiting until immediately before the project deadline to upload work.

The group will use GitHub throughout the entire project to track progress and maintain the final project files.
